\section{Introduction}
\label{sec:intro}

This guide is written for anyone who needs to verify the behaviour of the Drixal Service Platform manually: developers, QA engineers, and product owners running a demo.

The platform is a multi-tenant service-management application built with Nuxt~4, TypeScript, MongoDB and Mongoose. It connects public service discovery, customer requests, provider review and approval, order conversion, assignment, scheduling, and private customer tracking in one role-aware workflow.

Throughout this guide, the term \textbf{flow} means a complete user journey that starts with an action (for example, signing in or opening the marketplace) and ends with a verifiable outcome (for example, an order created, a company approved, or a service published).

\section{Before You Start: Setup}
\label{sec:setup}

\begin{enumerate}[leftmargin=2em, itemsep=2pt]
  \item \textbf{Install dependencies:} \texttt{npm install}
  \item \textbf{Create the environment file:} copy \texttt{.env.example} to \texttt{.env} and set a MongoDB connection string:
  \begin{lstlisting}[style=drixal]
# MongoDB connection string used by the server runtime
NUXT_MONGOOSE_URI=mongodb://127.0.0.1:27017/drixal

# Runtime environment: development | production
NODE_ENV=development

# Public origin used for CSRF / origin checks
APP_ORIGIN=http://localhost:3000

# Demo password used by the seed script (must match .env if set)
DEMO_PASSWORD=DrixalDemo123!
  \end{lstlisting}
  \item \textbf{Seed the demo data:} \texttt{npm run seed}
  \item \textbf{Start the development server:} \texttt{npm run dev}
  \item \textbf{Open the application:} \url{http://localhost:3000}
\end{enumerate}

\begin{notebox}
  The seeded demo accounts all use the password \texttt{DrixalDemo123!} unless \texttt{DEMO\_PASSWORD} was changed \emph{before} running \texttt{npm run seed}. If you changed it, replace the password everywhere below.
\end{notebox}

\section{Common Testing Notes}
\label{sec:common}

\begin{itemize}[leftmargin=2em, itemsep=2pt]
  \item \textbf{Login:} all protected flows start at \texttt{/auth/login}. After signing in you land on the workspace home of the selected context.
  \item \textbf{Public marketplace:} \texttt{/marketplace} works without any login. Only \emph{published}, \emph{active} services of \emph{approved} companies appear.
  \item \textbf{Cross-tenant isolation:} while testing, verify that company-scoped data is never visible outside the selected company (for example, requests/orders belonging to Cool Air Services must not appear under TechFix).
  \item \textbf{Reset state:} re-run \texttt{npm run seed} to restore the demo database to its original state between test runs.
  \item \textbf{Responsive behaviour:} the interface is bilingual (Arabic RTL / English LTR) and responsive. Verify key flows at desktop and mobile widths, and switch the language with the preference control when present.
\end{itemize}

\section{Flow: Customer Journey (Public + Personal)}
\label{sec:flow-customer}

This flow exercises the public marketplace, authentication, request submission, and private customer tracking.

\account{Customer}{customer@drixal.example}{DrixalDemo123!}

\subsection{1. Browse the marketplace (no login)}
\begin{enumerate}[leftmargin=2em, itemsep=2pt]
  \item Open \url{http://localhost:3000/marketplace}.
  \item Verify the marketplace lists published services: AC Maintenance, AC Installation, Emergency AC Repair (Cool Air Services) and Laptop Maintenance, Remote IT Support (TechFix).
  \item Use the search box and filters (category, city, min price, max price). Verify the URL query string updates (e.g.\ \texttt{?search=ac\&category=home-services\&city=Alexandria}).
  \item Confirm that \emph{Nile Home Care} does not appear (it is pending approval).
\end{enumerate}

\subsection{2. Open a service detail page}
\begin{enumerate}[leftmargin=2em, itemsep=2pt]
  \item Open a service, e.g.\ \texttt{/marketplace/companies/cool-air-services/services/ac-maintenance}.
  \item Verify the price (500 EGP), duration (90 min), location type, scheduling requirement, category badge, and provider profile card are displayed.
  \item The request form is visible; submitting requires login.
\end{enumerate}

\subsection{3. Sign in as the customer}
\begin{enumerate}[leftmargin=2em, itemsep=2pt]
  \item Choose \emph{Sign in} from the service detail page, or go to \texttt{/auth/login}.
  \item Sign in with \texttt{customer@drixal.example} / \texttt{DrixalDemo123!}.
  \item You land in the \emph{Personal} workspace (\texttt{/customer}).
\end{enumerate}

\subsection{4. Submit a service request}
\begin{enumerate}[leftmargin=2em, itemsep=2pt]
  \item Return to the AC Maintenance service detail page.
  \item Fill in the request form: name, phone, optional email/city, preferred date, and a short message.
  \item Submit the request and verify the success confirmation appears.
\end{enumerate}

\subsection{5. Track the request privately}
\begin{enumerate}[leftmargin=2em, itemsep=2pt]
  \item Go to \texttt{/customer/requests} (Personal workspace $\rightarrow$ Requests).
  \item Verify the newly submitted request appears with status \texttt{NEW} (or the current seeded status) and shows the provider name.
\end{enumerate}

\subsection{6. Track orders (after provider action)}
\begin{enumerate}[leftmargin=2em, itemsep=2pt]
  \item Go to \texttt{/customer/orders} and \texttt{/customer/orders/\$id}.
  \item Verify the seeded order \texttt{SO-1001} (AC Maintenance, \texttt{IN\_PROGRESS}) and \texttt{SO-1002} (AC Installation, \texttt{SCHEDULED}) are visible with their service lines and summary.
  \item Confirm the customer can see the provider name, scheduled date, assigned technician, and priority, but not internal costs or notes.
\end{enumerate}

\section{Flow: Company Manager (Provider Operations)}
\label{sec:flow-manager}

This is the most comprehensive flow. It covers service management, the request inbox, order conversion, service lines, scheduling, customers, and company profile.

\account{Company Manager}{manager@coolair.example}{DrixalDemo123!}

\subsection{1. Sign in and select the company}
\begin{enumerate}[leftmargin=2em, itemsep=2pt]
  \item Sign in at \texttt{/auth/login}.
  \item Use the workspace switcher to select \textbf{Cool Air Services}.
  \item You land in the Company Admin workspace (\texttt{/company-admin}).
\end{enumerate}

\subsection{2. Dashboard overview}
\begin{enumerate}[leftmargin=2em, itemsep=2pt]
  \item Verify the metrics (services, open requests, active orders, customers) reflect the seeded data.
  \item Verify the work-queue table lists active orders and the demand-pipeline panel shows request statuses.
\end{enumerate}

\subsection{3. Service catalog management}
\begin{enumerate}[leftmargin=2em, itemsep=2pt]
  \item Open \texttt{/company-admin/services}.
  \item Create a new service (\texttt{/company-admin/services/new}): name, description, category, location type, pricing type/amount, duration, scheduling requirement.
  \item Verify the new service appears with status \texttt{DRAFT}.
  \item Edit the service (\texttt{/company-admin/services/\$id/edit}) and save the changes.
  \item \textbf{Publish} the service and verify its status becomes \texttt{PUBLISHED}.
  \item Confirm the published service now appears in the public marketplace.
  \item \textbf{Unpublish} the service and confirm it disappears from the marketplace.
  \item Use search and the publication-status filter in the list.
\end{enumerate}

\subsection{4. Request inbox (approve / reject / convert)}
\begin{enumerate}[leftmargin=2em, itemsep=2pt]
  \item Open \texttt{/company-admin/requests}.
  \item The seeded approved request (from the customer flow) is listed; filter by status using the selector.
  \item \textbf{Approve} a \texttt{NEW} request, verify it becomes \texttt{APPROVED}.
  \item \textbf{Reject} a request, verify the confirmation dialog and the status change to \texttt{REJECTED}.
  \item \textbf{Convert} an \texttt{APPROVED} request into a service order; verify the request becomes \texttt{CONVERTED} and a new order is created.
\end{enumerate}

\subsection{5. Service orders}
\begin{enumerate}[leftmargin=2em, itemsep=2pt]
  \item Open \texttt{/company-admin/orders}.
  \item Verify seeded orders \texttt{SO-1001} and \texttt{SO-1002} with statuses, priorities, assignments, and scheduled dates.
  \item Open the order detail (\texttt{/company-admin/orders/\$id}).
  \item Verify the overview, the service-lines table, and the summary panel.
  \item \textbf{Add a service line} (title, quantity, assignee, cost).
  \item \textbf{Update a line assignment} and status via the inline controls.
  \item \textbf{Assign the order} to a company member from the summary panel.
\end{enumerate}

\subsection{6. Schedule}
\begin{enumerate}[leftmargin=2em, itemsep=2pt]
  \item Open \texttt{/company-admin/schedule}.
  \item Verify scheduled orders are grouped by date with customer, service, assignee, and status.
\end{enumerate}

\subsection{7. Customers directory}
\begin{enumerate}[leftmargin=2em, itemsep=2pt]
  \item Open \texttt{/company-admin/customers}.
  \item Verify the seeded customers (Demo Customer, Delta Co.) appear with contact details.
  \item Use the search box; verify pagination and the empty/error states when applicable.
\end{enumerate}

\subsection{8. Company profile}
\begin{enumerate}[leftmargin=2em, itemsep=2pt]
  \item Open \texttt{/company-admin/company}.
  \item Verify the company name, slug, status badge (\texttt{APPROVED}), location, and description.
\end{enumerate}

\subsection{9. Multi-company membership}
\begin{enumerate}[leftmargin=2em, itemsep=2pt]
  \item Switch to \textbf{TechFix} via the workspace switcher.
  \item Verify TechFix shows its own services (Laptop Maintenance, Remote IT Support) and an empty request/order queue, proving tenant isolation.
\end{enumerate}

\section{Acceptance Checklist}
\label{sec:acceptance}

Use this checklist to sign off a test run.

\begin{enumerate}[leftmargin=2em, itemsep=2pt]
  \item Public marketplace works without login and lists only eligible services.
  \item Sign in, sign out, and workspace switching work for all roles.
  \item The customer can submit a request and track requests and orders privately.
  \item The manager can create/edit/publish/unpublish services and see the marketplace change.
  \item The manager can approve, reject, and convert requests.
  \item Orders support service lines, assignments, and scheduling.
  \item The technician sees only read-only operational views.
  \item The viewer has read-only access everywhere.
  \item The super admin can approve, reject, suspend, and reactivate companies, and the marketplace reacts accordingly.
  \item A new company starts \texttt{PENDING} and cannot publish until approved.
  \item Tenant isolation holds: no cross-company data leaks.
  \item All pages show loading, error, and empty states appropriately.
  \item The UI is usable in English LTR and Arabic RTL, and at desktop and mobile widths.
  \item Re-running \texttt{npm run seed} restores the demo database.
\end{enumerate}
